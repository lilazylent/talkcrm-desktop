# Подключение сотрудника через браузер

## Изменение требований — 03.10.2026

Пользователь не имеет прав администратора amoCRM. Добавить локальный вход на официальном сайте в отдельном окне приложения. Пользователь сам вводит пароль и коды; приложение не получает поля формы. OAuth остаётся альтернативой для существующей интеграции.

Первая проверяемая версия: проверка чтения стандартных GET API через авторизованную браузерную сессию. Если сайт не предоставляет такой доступ, подключение не считается успешным и прежний кэш не заменяется. DOM-парсер и полнота данных не заявляются до исследования реального авторизованного интерфейса. Для Контур.Толка сначала нужен адрес доступного пользователю интерфейса записей.

## Границы и безопасность

- Отдельная непостоянная Electron session, без preload, Node и IPC приложения. Навигация только на HTTPS amoCRM; разрешения и загрузки отключены.
- Только cookie официальных доменов выбранного аккаунта и авторизации сохраняются после проверки в Windows encrypted store. Пароли, HTML и содержимое формы не читаются. Browser localStorage и cache не сохраняются на диск.
- GET клиент, пагинация, фильтрация по подтверждённому current_user_id и транзакционный кэш используют существующий проверенный код.
- Перезапуск открывает локальный кэш без сети. Ручная синхронизация восстанавливает сессию; истёкшая сессия требует нового входа.

## Сценарии приёмки

1. Чужие домены, HTTP, URL с credentials и повреждённые cookie отвергаются.
2. Ответ account с валидными id/current_user_id позволяет сохранить сессию и режим browser; cookie отсутствуют в SQLite и renderer.
3. 401/403, HTML вместо JSON, некорректный пользователь не создают подключение и не меняют кэш.
4. При browser sync OAuth token endpoint и Authorization header не используются.
5. Отключение удаляет обе формы секретов и очищает собственные browser sessions; кэш сохраняется по выбору пользователя.
6. Migration 003 сохраняет старые OAuth аккаунты. UI предлагает вход сотрудника первым, отдельную проверку после ручного входа и честное сообщение об ограничениях.
7. Проверить сборку, тесты, браузерный UI и реальное изолированное Electron окно. Реальный вход и полнота синхронизации требуют действия пользователя.
