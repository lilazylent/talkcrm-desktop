# Контур.Толк — Phase 3, версия 0.3.0

## Проверенные источники

Публичный OpenAPI: https://developer.kontur.ru/doc/talk.public.api, проверен 04.10.2026. Пользовательский режим подтверждён структурированными JSON-запросами собственного изолированного окна TalkCRM после ручного входа пользователя через Яндекс. Названия, текст разговоров, cookies, значения Authorization и идентификаторы пользователей/записей не включены в этот документ. Обезличенные формы ответов: `validation/kontur-observed-shapes.json`.

## Два режима и общий контракт

`KonturTalkAdapter` → `TalkImport` → SQLite. `SessionTalkAdapter` и `ApiTalkAdapter` используют одну нормализацию. Обычный сотрудник выбирает «Обычный вход»; API требует ключ администратора и остаётся отдельным способом подключения. API-контракты сверены с OpenAPI и проверены синтетическими тестами; живой API-ключ пользователем не предоставлен.

### Пользовательская сессия: наблюдавшиеся операции

Все перечисленные операции — GET на HTTPS-домене выбранного пространства. Авторизация: категория `Authorization: Session`; значение остаётся в привилегированном процессе. Его получает обработчик запросов только собственной `persist:kontur-talk`, включая запросы service worker. Cookies других браузеров и установленного отдельного приложения не извлекаются.

| Назначение | Обезличенный путь | Структура и пагинация |
| --- | --- | --- |
| Текущий профиль | `/api/context` | `user.key`, firstname/surname/patronymic, email при наличии; валидация обязательного key |
| Записи, доступные пользователю | `/api/recordings?skip={offset}&top={limit}&initiator=false` | `{recordings: [...]}`; skip/top, страница 100, завершение на неполной странице; false наблюдался для «Все» |
| Метаданные и полные участники | `/api/recordings/{recordingKey}` | id, title, createdDate, duration, status, participants/userInfo, conferenceKey; вложенные медиа-ссылки не скачиваются |
| Материалы | `/api/recordings/v2/{recordingKey}/summary` | transcriptionV2, shortSummaryV2, protocolV2; статус каждого независим |
| Фактическое время недавних конференций | `/api/conferencesHistory/recent` | массив объектов conference с key/startTime/endTime; только точное совпадение conferenceKey, без сопоставления по названию или комнате |

Также наблюдались calendar, externalUpload/history и access. Они не нужны для текущего импорта; права доступа и внешние загрузки приложение не меняет. Календарь в момент проверки был пуст. Протокол возвращался как notAvailable.

Записи показаны источником от новых к старым; адаптер проверяет этот порядок и останавливает импорт при его изменении. История ограничена последними 90 днями по source createdDate; после достижения более ранней даты дальнейшие страницы не читаются. Ограничение 5 000 записей защищает от неограниченного обхода. Дата создания записи не используется как время начала разговора. Когда конференции нет в недавней истории, начало остаётся неизвестным.

### Официальный API

| Операция | GET-путь | Контракт |
| --- | --- | --- |
| Проверка ключа/обнаружение | `/api/Domain/recordings/v2` | X-Auth-Token; startFrom/startTo, top=100, orderMode=byTimeNewFirst, pageToken; entities/nextPageToken |
| Полные участники | `/api/Domain/recordings/{recordingKey}/participants` | массив, skip/top, максимальный top=100 |
| Материалы | `/api/recordings/v2/{recordingKey}/summary` | общий V2-контракт |

Публичная модель записи Domain не гарантирует conferenceKey, фактическое начало и статус медиа. При отсутствии этих полей используются отдельная идентичность записи, неизвестное время и not_available; значения не выдумываются. Ключ API хранится отдельно от SQLite через Windows safeStorage/DPAPI.

## Ошибки и границы транспорта

- Только централизованные разрешённые GET-пути; внешние хосты, загрузка видео, изменяющие операции и перенаправления транспортом отклоняются.
- 401: needs_login, «Войдите снова»; 403: отказ без поиска обходных URL. 403/404 отдельных материалов дают недоступные артефакты, сохраняя доступные метаданные записи.
- 429/5xx и сетевой сбой: не больше трёх попыток; сетевой timeout 20 секунд, JSON-ответ не более 25 MB.
- Неизвестный статус, неверный DTO или повторяющийся курсор: обновление останавливается. До успешной загрузки всего ограниченного набора SQLite не изменяет материалы.
- Журнал содержит только источник, локальный account/run ID, время, состояние и счётчики. Исходные сообщения ошибок, заголовки и тела ответов не логируются.

## Сессия Electron

Выделенная постоянная partition; удалённое окно без preload, Node и IPC, с sandbox/contextIsolation/webSecurity. Основной React renderer имеет свой preload и не получает секреты. Разрешены только рабочий домен и наблюдавшиеся официальные страницы Контура/Яндекса. Разрешения устройства и загрузки запрещены. Пароль и коды пользователь вводит вручную на официальной странице. После проверки окно скрывается, при закрытии TalkCRM закрывается и окно сессии. Отключение очищает только выделенную partition и текущий ключ API.

Сессия использует стандартное локальное хранилище Chromium в выделенной partition. Не следует утверждать, что все виды browser storage, в том числе localStorage, шифруются DPAPI: такая гарантия дана только для отдельного хранилища API-ключа. Повторный вход требуется при истечении сессии.

## Идентичность и сохранение

Миграция 004 расширяет существующие meetings, добавляет таблицы участников, артефактов, сегментов, алиасов source ID и журнала. Профиль, настройки и amoCRM сохраняются. Источник = kontur_talk. Локальный UUID встречи отличается от recordingKey и conferenceKey. Несколько записей одной конференции объединяются по подтверждённому conferenceKey. Идентификаторы сегментов сохраняются при повторном и исправленном импорте. Данные разделены по домену и действительному профилю; смена профиля не импортирует в чужой кэш.

Синхронизация перечитывает ограниченный недавний список и readiness материалов. Точный change feed в наблюдённых контрактах отсутствует. ETag/304 применяется там, где его отдаёт источник, и разделён по авторизации. Неизменённые сегменты не пересоздаются; новые/исправленные обновляются. Отсутствующий ранее артефакт проверяется при следующем ручном обновлении. Готовый кэш сохраняется при временной недоступности; явно hidden пересказ и скрытые chunks удаляются из видимого локального материала.

Транскрипция: исходные speaker/chunk IDs, имена, текст, start/endTimeOffsetInMillis без округления. Пересказ и протокол: исходные chunks с type, text, timestamp (секунды преобразуются в миллисекунды) и version. startedAt генерации не выдаётся за время её завершения. AI-генерации, CRM-привязки и CRM-записей в этой фазе нет.

## Интерфейс и проверка

Настройки: подключение, обновление, повторный вход, отключение с сохранением или явным удалением локального кэша. Список: пять фильтров; карточка: Обзор / Транскрипция / Пересказ / Протокол / Запись. CRM-связь нейтральна: «Пока не определена». Демо-встречи и демо-CRM не появляются рядом с активным реальным кэшем Толка. Отдельные реальные встречи/клиенты в этой фазе не сопоставляются.

Транскрипция читается локально по 100 сегментов; запросы ограничены 200 на IPC. Поиск учитывает регистр кириллицы и не обращается к Толку. Проверен синтетический разговор из 20 000 сегментов в SQLite и браузере. Запись открывается по проверенной HTTPS-ссылке своего пространства; видео автоматически не скачивается.

Живая проверка на внутренних встречах пользователя: 4 записи → 3 встречи, 891 сегмент, 4 пересказа, 0 доступных протоколов. Повторная синхронизация и новый процесс сохранили локальные ID. См. `validation/kontur-live.json`. Наличие клиентских разговоров для проверки не требуется.
