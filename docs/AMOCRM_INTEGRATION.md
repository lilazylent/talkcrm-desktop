# Подключение amoCRM

## Вход сотрудника через браузер (0.2.1, требуется реальная проверка)

1. TalkCRM → Настройки → amoCRM → Подключить. Первым выбран «Вход через браузер».
2. Укажите `samosale.amocrm.ru` и нажмите «Открыть окно входа».
3. Самостоятельно войдите на официальном сайте в открытом окне. Пароль и коды не вводятся в форму TalkCRM.
4. Вернитесь в TalkCRM и нажмите «Проверить доступ и загрузить».

Приложение проверяет GET `/api/v4/account` через cookie собственной сессии. Только валидный ответ с ID аккаунта и пользователя создаёт подключение. Затем запускается стандартная синхронизация. Это проверяемый вариант доступа, его работоспособность для аккаунта сотрудника ещё не подтверждена. Если сайт отвечает 401/403 либо HTML вместо JSON, подключение не считается успешным. Парсинг веб-интерфейса ещё не реализован; нельзя обещать полноту данных до реального входа.

Окно сайта не имеет preload и IPC TalkCRM, использует sandbox и отдельную сессию в памяти. После успешной проверки выбранные cookie amoCRM сохраняются в Windows encrypted store отдельно от SQLite. Сессии обычного браузера не копируются. При истечении авторизации требуется повторный вход. Отключение удаляет OAuth и browser credentials и очищает собственные сессии приложения.

## Подготовка OAuth-интеграции

1. В amoМаркет своего аккаунта создайте приватную интеграцию. Создание требует прав администратора; приложение читает данные с правами пользователя полученного токена.
2. Задайте Redirect URI и сохраните его точное значение. Мастер использует ручной код из вкладки ключей; публичный OAuth-сервер не нужен.
3. Скопируйте ID интеграции и секрет. Получите свежий код авторизации: он действует 20 минут и обменивается однократно.
4. Откройте TalkCRM → Настройки → Интеграции → amoCRM → Подключить → Через интеграцию → Ввести данные.
5. Укажите домен company.amocrm.ru или поддомен, ID, секрет, Redirect URI и код. Нажмите «Подключить и загрузить».

Ключи вводятся в приложение. Пароль amoCRM не нужен. Принимается только HTTPS-поддомен amocrm.ru без пути, порта или стороннего адреса. Данные защищены Windows DPAPI на этом компьютере.

Если интеграцию подключил администратор, текущим пользователем может оказаться именно он. В настройках показан ID из /account: сравните его с ожидаемым ответственным.

## Данные и обновление

Загружаются ваши сделки, их компании и контакты со всеми связями и основным контактом, воронки/этапы, ваши задачи, примечания загруженных сделок и определения/значения пользовательских полей. Административный каталог пользователей не запрашивается. Ответственный показан как «Пользователь #ID». Сумма хранится числом; валютный знак отображается только при наличии валюты в API.

Без компании рабочее пространство строится по контакту; без обоих — по сделке. Недоступные сущности не подменяются выдуманными контактами.

После подключения начинается первая синхронизация. Далее используйте «Обновить» сверху или «Синхронизировать» в настройках. Приложение полностью просматривает доступную область с пагинацией: большой аккаунт может загружаться долго. Фонового опроса нет.

При старте сеть не вызывается: показывается локальный кэш и дата обновления. Источник переключается между Демо и amoCRM. В реальном режиме нет демонстрационных встреч; они появятся после Контур.Толк. С 0.5.0 задачи, сделки, контакты, компании и примечания можно изменять из рабочего места клиента; запись подтверждается amoCRM.

Частичная ошибка означает, что основная область обновлена, а перечисленные категории сохранены из предыдущего кэша. Ошибка основной области не заменяет пригодные данные. Отсутствующая запись помечается «Нет в последней синхронизации», а не удаляется. Карточка показывает последние 20 примечаний; весь загруженный набор сохранён локально.

## Запись в amoCRM (0.5.0)

Все изменения отправляются только по явному действию пользователя и только для разрешённых маршрутов: `PATCH` сделок, контактов и компаний, создание и изменение задач, создание и изменение примечаний. Удаление не поддерживается. После ответа amoCRM запись читается заново и только эта версия сохраняется в кэш. Подробности: [CRM_WORKSPACE.md](CRM_WORKSPACE.md), правила — [AMOCRM_WRITE_SAFETY.md](AMOCRM_WRITE_SAFETY.md).

В режиме входа сотрудника запись идёт той же изолированной cookie-сессией, что и чтение, с заголовком `X-Requested-With`. Принимает ли amoCRM изменения по cookie-сессии конкретного аккаунта, подтверждается только реальной проверкой; при отказе (401/403) TalkCRM показывает понятную ошибку и ничего не меняет локально, а запись остаётся доступной через OAuth-интеграцию.

Дополнительно синхронизируются типы задач (`/api/v4/account?with=task_types`), группы полей и примечания контактов/компаний. История загружается точечно из `/api/v4/events` для открытого клиента.

## Отключение

Настройки → amoCRM → Отключить → подтвердить. По умолчанию удаляются ключи, кэш сохраняется. Для удаления локальных записей аккаунта явно отметьте «Также удалить локальный кэш». Демо, профиль и обычные настройки сохраняются.

## Ошибки

| Ситуация | Действие |
| --- | --- |
| 401 / сбой обновления авторизации | Получите свежий код и подключите заново |
| 402 | Проверьте оплату аккаунта |
| 403 | Проверьте права пользователя/интеграции; при записи — «У вас нет прав на это изменение в amoCRM.», без повторов |
| 404 | Сущность удалена или недоступна |
| 422 | Проверьте настройки; неподдерживаемый фильтр сделок обрабатывается автоматически |
| 429 / 5xx | Клиент выполняет ограниченные повторы; при сохранении ошибки обновите позже |
| Нет сети | Просматривайте кэш, повторите обновление после восстановления связи |
| Нет шифрования Windows | Подключение не сохраняется в открытом виде; проверьте запуск под своим Windows-пользователем |

При неоднозначном сбое refresh token требуется повторное подключение, чтобы не использовать уже потраченный токен.

## Приёмка реального аккаунта

Проверьте текущего пользователя, выборку сделок, компанию/контакты, этапы, задачи, примечания и поля. Повторное обновление не создаёт дублей. Перезапуск показывает кэш. Изменение задачи в CRM появляется после обновления. Запись из TalkCRM проверяется только на тестовой записи, назначенной пользователем. Проверка фиксируется только после реального подключения пользователем.
