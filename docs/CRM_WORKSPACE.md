# Рабочее место клиента и запись в amoCRM (Phase 5, 0.5.0)

amoCRM остаётся главной системой записи. TalkCRM — интерфейс менеджера: каждое изменение уходит в amoCRM, подтверждается ответом amoCRM и только потом попадает в локальный кэш и на экран.

```text
Действие пользователя → типизированная команда (CrmCommand) → IPC crm:write
→ CrmService.execute → validateCommand (метаданные кэша) → журнал crm_operations (sending)
→ свежее чтение записи из amoCRM → проверка конфликта → PATCH/POST только изменённых ключей
→ повторное чтение результата → обновление crm_entities → confirmed → перезагрузка снимка в UI
```

## Модель рабочего места

Маршрут `/clients/:id?deal=<id>`. Клиент — это компания, контакт или сделка без контакта (так же, как в Phase 2). Компания необязательна: клиент «контакт → сделка» без компании — основной сценарий реального аккаунта.

- **Шапка:** имя, компания (если есть), телефон, почта, ответственный, кнопки «Добавить примечание» и «Добавить задачу», «Обновить».
- **Сделки клиента:** если сделок несколько, выбирается одна; заголовок карточки всегда называет редактируемую сделку. Этапы, задачи, поля и примечания разных сделок не смешиваются. Выбор хранится в адресе.
- **Факты:** сделка, этап, воронка, бюджет, следующая задача.
- **Вкладки:** «Обзор», «История», «Задачи», «Встречи». Массив вкладок расширяемый — место под «Чат» и «Звонки» оставлено, но кнопок-заглушек нет.
- **Обзор:** карточка сделки (поля, бюджет, этап), встречи по сделке, карточка контакта (имя, все телефоны и почты, поля), карточка компании (если есть), «Важные поля», последняя подтверждённая встреча, ближайшие задачи, последние действия.

## Редактирование полей

`EntityCard` один для сделки, контакта и компании. По умолчанию — просмотр; «Редактировать» включает поля, «Сохранить»/«Отмена». Отслеживаются изменённые ключи; при уходе со страницы с несохранёнными правками показывается предупреждение (меню, кнопка «Клиенты», смена сделки).

Динамический редактор строится по метаданным полей amoCRM (`crm_fields`), без выдуманных значений списков:

| Тип amoCRM | Редактор | Значение в запросе |
| --- | --- | --- |
| text, textarea | поле / многострочное поле | `{value}` |
| numeric | число (пробелы и запятая допустимы) | `{value: "1250.5"}` |
| checkbox | флажок | `{value: true}` |
| select, radiobutton | список из enums | `{enum_id}` |
| multiselect | набор чипов из enums | `[{enum_id}…]` |
| date, birthday | дата | `{value: unix}` (локальная полночь) |
| date_time | дата и время | `{value: unix}` |
| url | адрес http(s) | `{value}` |
| multitext (PHONE, EMAIL…) | список значений с типом (Рабочий, Мобильный…) | все значения с `enum_code` |

Остальные типы (file, tracking_data, smart_address, legal_entity, items, chained_list и любые неизвестные) показываются только для чтения с пометкой «Только в amoCRM» и никогда не попадают в запрос. Поля сгруппированы по группам amoCRM (если синхронизированы), заполненные — выше пустых; «Показать все поля» и поиск по названию. Пустое поле отправляется как `values: null`.

Несколько телефонов и почт: отправляется полный список значений поля, поэтому вторичные значения и их типы (WORK, WORKDD, MOB, HOME…) сохраняются, пока пользователь сам их не удалит.

## Этап и воронка

Кнопка этапа открывает список этапов текущей воронки (цвета из amoCRM, «Неразобранное» скрыто). Обычный этап сохраняется сразу. Переход в «Успешно реализовано» (142), «Закрыто и не реализовано» (143) и возврат закрытой сделки в работу требуют подтверждения — и в интерфейсе, и в main-процессе (`confirmTerminal`). При выборе другой воронки нужно явно выбрать этап этой воронки; пара воронка/этап проверяется по кэшу. Воронки и этапы не создаются и не редактируются.

Бюджет — целое неотрицательное число в валюте аккаунта, без пересчёта; пустое значение сохраняется как 0.

## Задачи

Группы «Просрочено», «Сегодня», «Предстоящие», «Выполнено» (по локальному дню). Форма: «Что сделать», «Когда» (дата, время, «Сегодня / Завтра / Через неделю»), «Тип» (типы задач аккаунта из `account?with=task_types`, иначе «Звонок»/«Встреча»), «Привязать к» (выбранная сделка по умолчанию, затем контакт, компания). Ответственный — текущий менеджер. Время переводится из локального времени в unix-секунды без сдвига часового пояса.

Изменение текста, срока и типа — `PATCH /api/v4/tasks/{id}` без пересоздания. Выполнение — флажок → окно «Результат» → `is_completed: true` и `result.text`. Задача становится выполненной только после подтверждения amoCRM; локальной отметки для задач amoCRM нет.

**Возврат задачи в работу не реализован.** Документация amoCRM не гарантирует безопасное снятие `is_completed`, и проверить это без тестовой задачи в реальном аккаунте нельзя. Выполненные задачи в TalkCRM только для чтения.

## Примечания

«Добавить примечание» создаёт обычное (`common`) примечание у выбранной сделки, а без сделки — у контакта. Ctrl+Enter добавляет. Идентификатор примечания из ответа amoCRM сохраняется в журнале операций; редактировать можно только примечания, созданные через TalkCRM. Примечания amoCRM других авторов и системные записи (`service_message`, звонки, SMS, файлы…) — только для чтения.

## История

`composeTimeline` объединяет события amoCRM (`/api/v4/events` для сделок, контакта и компании клиента, по 10 id, до 5 страниц по 100), примечания, задачи и подтверждённые встречи Толка. Источник сохраняется (`amo_event`, `amo_note`, `amo_task`, `kontur_meeting`). Повторы событий «примечание добавлено» и «задача создана/выполнена» не дублируют записи из кэша.

Нормализованные категории: создание/удаление/восстановление сделок, контактов, компаний; смена этапа (`Переговоры → Согласование`); изменение бюджета, названия, ответственного; изменение дополнительного поля (`custom_field_{id}_value_changed`); задачи (создание, выполнение, текст, срок, тип, результат); примечания; привязки и теги; звонки, SMS и сообщения amoCRM (только как факт); прочее — «Изменение в amoCRM». Сырые коды и JSON не показываются. Фильтры: «Все», «Примечания», «Задачи», «Изменения», «Встречи».

## Встречи

В рабочем месте показываются только подтверждённые связи Phase 4: встреча с подтверждённой сделкой — в контексте этой сделки, без сделки — на уровне клиента. Предложенные и непривязанные встречи остаются только в разделе «Встречи».

## Обновление данных

При открытии карточки, если история не загружалась больше 10 минут, выполняется точечное обновление: сделки клиента (`filter[id]`), их контакты и компании, задачи этих сущностей, примечания и события. Полная синхронизация аккаунта при этом не запускается и не помечает чужие записи недоступными. Кнопки «Обновить» — в шапке и в истории. Реального времени и вебхуков нет.

## Без соединения

Кэш доступен для просмотра. Если amoCRM отключена или нет сети, все кнопки изменения неактивны и показывается «Нет соединения с amoCRM. Данные доступны только для просмотра.» Изменения не ставятся в очередь и не отправляются позже.

## Повторное использование

Будущие предложения AI/шаблонов должны формировать те же `CrmCommand` и после подтверждения человеком вызывать тот же `crm:write`. Отдельного пути записи не будет.

Правила безопасности: [AMOCRM_WRITE_SAFETY.md](AMOCRM_WRITE_SAFETY.md).
