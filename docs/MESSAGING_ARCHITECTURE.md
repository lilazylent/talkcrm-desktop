# Переписка с клиентами (Phase 6, 0.6.0)

## Выбранный путь

Phase 6 реализована на **официальном amoCRM Talks API** (`GET /api/v4/talks`). Это единственный путь, который даёт TalkCRM доступ к перепискам существующих каналов (WhatsApp, Telegram и других интеграций), не выдавая себя за чужой канал и не воспроизводя внутренние запросы веб-интерфейса amoCRM.

Talks API возвращает **метаданные переписки**: id беседы, контакт, сделку, канал (`origin`), источник, статус, «в работе», «прочитано», даты. **Текста сообщений в этом API нет**, отправки тоже нет. Поэтому чтение и отправка сообщений выполняются в самой amoCRM: TalkCRM открывает нужную карточку amoCRM в системном браузере.

Рассмотренные и не реализованные варианты:

- **Официальный Chats API** требует собственного зарегистрированного канала (channel id, secret, подписанные запросы). Чужие каналы сторонних виджетов через него недоступны, и TalkCRM не выдаёт себя за них. При появлении собственного канала TalkCRM его можно подключить отдельным адаптером.
- **Воспроизведение внутренних запросов веб-интерфейса amoCRM через сессию** не реализовано: этот путь опирается на недокументированное поведение и выходит за рамки безопасного подхода, принятого в проекте.
- **Прямые интеграции** (Telegram Bot API, WhatsApp Business API, API сервиса-подключения мессенджеров) возможны в будущем при наличии собственных официальных доступов.

## Модель данных

Миграция 007, таблица `crm_talks` (account_id, talk_id, chat_id, contact_id, entity_id, entity_type, origin, source_id, status, is_in_work, is_read, created_at, updated_at, last_seen_at, availability). Связь с клиентом — только по `contact_id` из amoCRM, без угадывания по имени. Сделка показывается, только если amoCRM вернула `entity_type = lead`. Повторная синхронизация обновляет те же строки по `talk_id`; пропавшие беседы помечаются недоступными, а не удаляются. Если шаг загрузки переписок не выполнился, прежний кэш сохраняется.

Домен: `CrmTalk` (`src/domain/crm.ts`), помощники `src/domain/talks.ts` (понятные названия каналов, различение нескольких источников одного мессенджера, статус, непрочитанные).

## Синхронизация

- Полная синхронизация amoCRM: необязательный шаг «Загружаем переписки» — `GET /api/v4/talks` с `filter[contact_id][]` для синхронизированных контактов, по 50 id, до 250 записей на страницу.
- Точечное обновление карточки клиента: переписки контактов этой карточки.
- Только GET; метод закрытия беседы (`POST /talks/{id}/close`) не используется и не входит в белый список записи.

## Интерфейс

- **Вкладка «Чат»** в рабочем месте клиента: переписки по каналам (WhatsApp, Telegram, Viber, ВКонтакте, Авито и др.; неизвестные — «Другой канал»), несколько источников одного мессенджера показаны раздельно («WhatsApp · источник 1/2»), статус, «Непрочитано», связанная сделка, даты, кнопка «Открыть в amoCRM» (карточка сделки, если беседа к ней привязана, иначе карточка контакта).
- **Обзор:** блок «Последняя переписка».
- **Раздел «Сообщения»:** все переписки ваших клиентов, фильтры «Все / Непрочитанные», канал, поиск по клиенту; счётчик непрочитанных в меню.
- Переписка отделена от примечаний, задач и истории: композитора сообщений и смешанной ленты нет.

`crm:openInAmo` в main-процессе открывает только `https://<домен аккаунта>/leads|contacts/detail/<id>` для записи, которая есть в локальном кэше.

## Безопасность и приватность

Тексты сообщений, вложения, куки и токены TalkCRM не получает и не хранит. В отчётах и логах — только количества и категории каналов. Обработки переписки внешним AI нет.

## Ограничения

- Нет текста сообщений, истории, вложений, статусов доставки и отправки внутри TalkCRM — это доступно в amoCRM.
- Признак «прочитано» отражает состояние amoCRM на момент последнего обновления; TalkCRM его не меняет.
- Названия источников (номер или название подключения) Talks API не отдаёт; показывается порядковый номер источника.
