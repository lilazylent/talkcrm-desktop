# Phase 3 — Контур.Толк

## Поведение и границы

Два адаптера (официальный API и собственная пользовательская сессия) возвращают общие встречи, участников, артефакты и сегменты транскрипции. Обычный сотрудник подключается непосредственно через официальную страницу Толка в изолированной постоянной Electron-сессии. Пароли и одноразовые коды приложение не получает. Импорт доступных записей за последние 90 дней, обновление по стабильным идентификаторам, повторная проверка готовящихся артефактов. Видео не скачивается. Привязка к CRM и генерация AI исключены из этой фазы.

## Порядок

1. Проверить публичный OpenAPI и реальные структурированные запросы собственного окна Толка после ручного входа пользователя; записать обезличенные контракты.
2. Добавить доменную модель и миграцию существующих meetings с отдельными участниками, артефактами, сегментами и журналом синхронизации. Сохранить amoCRM и локальные данные.
3. Реализовать адаптеры, защищённую сессию, сервис синхронизации и ограниченный IPC.
4. Обновить настройки, список встреч, пять вкладок, локальный поиск и порционную загрузку длинной транскрипции.
5. Проверить реальный импорт, повторную синхронизацию, перезапуск и миграцию копии установленной базы; собрать и установить обновление.

## Проверяемые сценарии

- Обычный вход → доступная пользователю запись → точные имена и миллисекунды исходной транскрипции.
- Одна конференция с несколькими записями → одна встреча, отдельные артефакты; повторный импорт не создаёт дубликаты.
- processing → ready при следующем обновлении; временная ошибка сохраняет прежний кэш.
- 401 → «Войдите снова»; 403 не запускает поиск обходных URL.
- Подмена домена, внешняя ссылка, чужой IPC, медиа-загрузка → отклонение.
- Отключение → удалена только авторизация; явный purge удаляет локальные встречи выбранного подключения.
- Миграция копии текущей базы → сохранены профиль, настройки, CRM и старые встречи.
- 20 000 сегментов → ограниченный объём отрисовки, локальный поиск, отзывчивый интерфейс.

## Состояние

Публичный OpenAPI и реальные GET-запросы собственной сессии подтверждены. Реализованы оба адаптера, миграция 004, журнал, IPC, пять вкладок и локальный поиск. Живой импорт в копию базы: 4 записи / 3 встречи / 891 реплика / 4 пересказа / 0 протоколов. Повторная синхронизация и новый процесс сохраняют ID, профиль, настройки и amoCRM. В браузере проверены карточка, мастер, недоступный протокол и поиск по 20 000 реплик (100 элементов в DOM). Сборка 0.3.0 установлена. Реальный импорт и кнопка обновления подтверждены в установленном приложении; прежние строки всех CRM-таблиц, профиль, настройки и старые встречи сохранены. Итог: validation/PHASE3_REPORT.md.
